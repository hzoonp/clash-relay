# clash-relay 2.3.0

`2.3.0` is the Stability, Diagnostics, and Client Compatibility release for the v2 line. It hardens subscription admission, regional scheduling, DNS compatibility, runtime diagnostics, production observability, client verification, and qualification evidence without changing the Public Config v2 schema or the source-permission contract.

## Routing and admission

- Regional routing now compiles from one canonical region catalog, with broader provider aliases and first-class UK browsing/general/media/messaging/download support.
- AI regional preferences remain independently governed and continue to exclude HK and UK.
- High-confidence subscription status/support pseudo-nodes are rejected immediately after parsing without broad name matching that could remove legitimate traffic nodes.
- `subscription_1` remains browsing/AI-only, EMBY-labelled nodes remain excluded, and explicit multipliers strictly greater than 2x remain rejected.

## DNS and client compatibility

- Managed Fake-IP compatibility uses narrow reviewed exclusions for China Mobile authentication and selected banking domains.
- A fail-closed Fake-IP breadth audit rejects wildcard misuse, public-suffix-scale exclusions, and overlap with protected AI domains.
- The existing `cn_three_net` resolver design, ACL4SSR DNS policy, TUN/DNS leak boundaries, and normal overseas/AI resolver pools remain unchanged.
- A canonical client/DNS verification matrix now covers Windows and Android FlClash, System Proxy and TUN, multiple network classes, network transitions, carrier authentication, banking authentication, IPv4/IPv6, UK routing, and AI scenarios.

## Determinism and diagnostics

- Regional runtime integration tests use deterministic health-transition evidence rather than depending on scheduler timing, reducing false CI failures across pinned Mihomo versions.
- `clash-relay diagnose --candidate <config.yaml>` provides read-only aggregate candidate/runtime diagnostics for static validation, DNS compatibility, the six public scenario groups, and optional real-Mihomo startup smoke.
- Diagnose and production observability remain privacy-safe: node names, proxy hosts/IPs, credentials, subscription URLs, and raw child-process diagnostics are not emitted.

## Production observability and qualification evidence

- Production observability unifies aggregate source admission, endpoint qualification, browsing/AI health, DNS audits, Promotion Guard, publication decisions, and lifecycle state.
- Qualification evidence is separated into DNS, TCP, HTTPS, UDP, and AI failure planes so a generic timeout no longer hides the stage that failed.
- Production metrics persist bounded aggregate tuning evidence such as attempts, quorum, and timeout values for longitudinal review.
- Anti-false-kill behavior is preserved: TCP connect timeouts remain Reserve evidence, while inconclusive DNS evidence keeps the node.
- Tuning remains review-gated by longitudinal evidence; no threshold is changed automatically.

## Release and dependency maintenance

- The build backend pin advances from Hatchling 1.27.0 to 1.32.4 after exact-main revalidation through Python 3.11/3.12/3.13, deterministic generation, Routing V2, and the complete stable Mihomo matrix.
- Exact-SHA validation, source-only GitHub Releases, Promotion Guard, private Cloudflare KV publication, immutable release objects, and validated rollback remain unchanged.

## Upgrade and compatibility

`2.3.0` is additive for existing v2 users. It does not change:

- the Public Config v2 schema;
- the six public FlClash scenario names;
- subscription Secret names or source permissions;
- the fixed client-facing Cloudflare KV key;
- immutable release-object and current/previous-pointer semantics;
- the requirement that every production candidate pass the complete pinned stable Mihomo matrix.

No configuration-format migration or Secret migration is required for existing v2 deployments.
