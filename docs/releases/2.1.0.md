# clash-relay 2.1.0

`2.1.0` is the evidence-driven diagnostics release for the v2 clean-slate line. It improves Fork preflight parity, provider-neutral qualification observability, and the discipline around scheduler tuning without changing the public configuration schema or relaxing any production safety boundary.

## Production-parity preflight

- `clash-relay doctor --public-only` resolves the same Policy Model v2 scheduling fragment and registered ServiceQualification probes consumed by production.
- Public preflight validates service registration without contacting providers or exposing private runtime state.
- The doctor report exposes only safe readiness status and aggregate probe count.

## Provider-neutral qualification diagnostics

- Every registered `ServiceQualification` is projected into one common aggregate result shape.
- The shared result reports tested, qualified, rejected, live-tested/live-qualified, cache-pass/cache-fail, status, and classifier-style outcome counts.
- The qualification pipeline iterates the registry instead of adding OpenAI, Claude, Gemini, or future-provider branches.
- Unstructured outcome labels fail closed rather than becoming a channel for URLs, response bodies, or other private data.
- Node identities, proxy payloads, server addresses, subscription URLs, credentials, raw response bodies, and endpoint response data remain private.

## Operational SLO evidence gate

- The existing bounded private Operational SLO ring now reports an explicit `scheduler_tuning_evidence` decision.
- A tuning review requires at least 12 longitudinal production attempts, at least 4 candidate transitions, and a complete lifecycle p50/p95/max distribution.
- Insufficient evidence returns `insufficient_evidence`.
- `automatic_tuning_allowed` is always false.
- Public GitHub workflow logs continue to expose only whether private SLO persistence succeeded, not the private ring values.

## Scheduler tuning decision

No scheduler parameter is changed in `2.1.0`. The available public production evidence proves successful private SLO persistence but does not expose enough private aggregate history to justify a reviewed change. Therefore the conditional scheduler-tuning workstream is intentionally skipped rather than tuning from intuition.

Unchanged values include scheduler hysteresis, debounce behavior, cache TTLs, qualification retry counts, service qualification thresholds, Promotion Guard thresholds, and routing policy.

## Unchanged safety boundaries

- Public Config and runtime Policy Model remain v2-only.
- `subscription_1` remains limited to browsing and AI inventories.
- An explicit node multiplier strictly greater than `2.0` is rejected; exactly `2.0` remains eligible.
- Public deterministic subscription ordering remains `ingest_order`; the removed `priority` alias does not return.
- RuntimeGraph remains topology truth and the builder does not mutate topology after compilation.
- Python production stages do not restore Python-to-Python subprocess/stdout JSON orchestration.
- Production qualification remains provider-agnostic at the core pipeline boundary.
- Publication remains bound to an exact validated commit SHA and Promotion Guard remains fail-closed.
- Rollback continues to require versioned immutable release state, current policy audit, and the complete stable Mihomo matrix, with no legacy fallback.
- GitHub Releases remain source-only; generated production configuration, subscription data, node-level qualification results, Cloudflare KV state, scheduler/cache state, metrics, and Operational SLO state remain private.
