# clash-relay 2.2.0

`2.2.0` is the Architecture Convergence release for the v2 line. It consolidates the P11 architecture work without changing the public routing contract, loosening source isolation, or introducing scheduler tuning without evidence.

This note is prepared before version activation. The project version and changelog must move to `2.2.0` only after the complete P11 merge train is represented on `main`, live main-branch governance is enforced, and the production dry-run gate is clean.

## Production lifecycle convergence

- GitHub Actions keeps one production mutation entrypoint: `scripts/run_production_release.py`.
- Scheduler observation publication is lifecycle-owned rather than a second workflow write path.
- A dry run does not publish scheduler evidence, and scheduler evidence requires production metrics freshly published by the same lifecycle run.
- Post-commit scheduler observation remains best-effort and cannot retroactively invalidate a committed release.

## RuntimeGraph topology authority

- RuntimeGraph owns deterministic topology traversal used by downstream validation.
- Validator topology checks consume RuntimeGraph reachability and cycle detection instead of maintaining a parallel traversal implementation.
- Runtime graph snapshots are detached from caller mutation.

## Runtime-generation boundaries

- Browsing runtime hardening is independent from optional ACL group generation and cannot be skipped merely because ACL group specs are absent.
- Runtime configuration rendering is isolated behind `RuntimeConfigRenderer`.
- Rule loading, rendering, external target validation, RULE-SET binding, and final MATCH compilation are isolated behind `RuleCompiler`.
- The generator remains incrementally decomposed rather than being rewritten wholesale.

## Terminology and release engineering

- Internal deterministic source ordering uses `ingest_order` / `source_ingest_order`; legacy priority terminology is not restored as a compatibility alias.
- Reusable validation remains the release quality authority.
- Release workflow steps consume the exact validated SHA instead of duplicating weaker lint/test/coverage gates.
- Release metadata contracts keep project version, release notes, changelog indexing, and Unreleased comparison bases synchronized.

## Unchanged safety boundaries

- `subscription_1` remains limited to browsing and AI.
- Explicit node multipliers strictly greater than `2.0` remain rejected; exactly `2.0` remains eligible.
- AI routing continues to exclude CN/HK according to the canonical policy contract.
- Source-to-scenario reachability remains fail-closed before and after qualification.
- Production publication remains gated by qualification, Promotion Guard, the complete pinned stable Mihomo matrix, and exact-SHA validation.
- Generated production configuration, subscription URLs, node-level state, scheduler/cache state, metrics, and Cloudflare KV state remain private.
- GitHub Releases remain source-only.

## Release activation gate

Before tagging `v2.2.0`:

1. complete the P11 merge train on `main`;
2. verify live GitHub main-branch protection/ruleset enforcement;
3. run authoritative CI and Routing V2 Drift Guard on the exact final SHA;
4. run a production-parity `publish=false` dry run and verify zero persistent writes;
5. update `pyproject.toml` to `2.2.0`, add the `2.2.0` changelog entry, and move `[Unreleased]` to `v2.2.0...HEAD` in the same reviewed metadata change;
6. create only the source release from the exact validated SHA.
