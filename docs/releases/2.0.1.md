# clash-relay 2.0.1

`2.0.1` is a focused production hotfix release for the v2 clean-slate line. It does not change the public configuration schema, routing semantics, subscription permissions, qualification thresholds, scheduler policy, or release safety model.

## Fixed

- AI qualification now resolves probe declarations through the canonical Policy Model v2 `scheduling` fragment instead of passing the physical `policies.yaml` manifest to the low-level probe loader.
- Canonical v2 regression coverage verifies that OpenAI, Claude, and Gemini probe declarations are resolved from the declared scheduling fragment.
- Flat legacy policy input remains rejected; the fix does not restore any Policy Model v1 runtime compatibility path.

## Maintenance

- Phase-era test filenames left over after the v2.0 release were renamed to durable semantic names, and the v2 release audit now prevents new `test_p*.py` files from returning.

## Unchanged safety boundaries

- Public Config and runtime Policy Model remain v2-only.
- `subscription_1` remains limited to browsing and AI inventories.
- An explicit node multiplier strictly greater than `2.0` is rejected; exactly `2.0` remains eligible.
- Production qualification remains provider-agnostic at the core pipeline boundary.
- Publication remains bound to an exact validated commit SHA and Promotion Guard remains fail-closed.
- Rollback continues to require versioned immutable release state and the complete current stable Mihomo matrix, with no legacy fallback.
- GitHub Releases remain source-only; production configuration, subscription data, node-level qualification results, Cloudflare KV state, scheduler/cache state, metrics, and operational SLO state remain private.
