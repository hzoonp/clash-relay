# clash-relay 2.0.0

`2.0.0` is the clean-slate public contract for clash-relay. It completes the architecture cleanup and freezes the supported path from declarations and private subscription inputs to an exact validated Mihomo configuration and private production publication.

## Highlights

- Runtime configuration is v2-only: `config.yaml`, `subscriptions.yaml`, and Policy Model v2 are the supported public declarations.
- Subscription ordering is explicit as `ingest_order`; the removed `priority` public field has no runtime compatibility alias.
- `subscription_1` remains hard-limited to browsing and AI inventories. Nodes with an explicit multiplier strictly greater than `2.0` are rejected; exactly `2.0` remains eligible.
- Generation now follows the compiler boundary: declarations and subscription inventory -> `PolicyCompiler` -> immutable `RuntimeGraph` -> qualification -> `MihomoSerializer`.
- Internal Python stages use in-process typed application APIs. Python-to-Python subprocess/stdout JSON orchestration is not part of the production path.
- CI and publication are bound to an exact validated commit SHA. Third-party Actions are immutable-SHA pinned and Python dependencies install from hash-verified locks.
- Python 3.11, 3.12, and 3.13 quality gates include Ruff, static typing on application boundaries, unit tests, coverage floor, repository safety, architecture audits, and supply-chain audits.
- Production qualification uses the generic `ServiceQualification` registry. OpenAI, Claude, and Gemini are provider implementations; the main qualification pipeline is provider-agnostic.
- Operational SLO state is aggregate-only and best-effort. Qualification rejection, retry recovery, Promotion Guard blocks, lifecycle duration, and candidate churn never weaken publication gates.
- Production releases remain immutable SHA-256 objects in private Cloudflare KV with verified current/previous release pointers and compensating restoration on commit failure.
- v2 removes the legacy `previous-v1` rollback slot and fallback. Rollback now requires a versioned previous-release pointer, exact bytes, and a matching immutable manifest.

## Release qualification

A `v2.0.0` source release is created only after the reusable exact-SHA validation workflow succeeds. The release gate includes:

- deterministic fictional generation and byte comparison;
- Routing V2 drift validation;
- every stable Mihomo core listed in `tools/mihomo-versions.json`, including real startup/provider HEAD integration;
- fork/public declaration readiness;
- privacy/repository safety checks;
- Promotion Guard and release-transaction regression coverage;
- rollback and failure/chaos regression coverage.

GitHub Releases remain source-only. Generated production configuration, subscription responses, node-level qualification data, Cloudflare KV values, scheduler state, AI cache, production metrics, and operational SLO state are private and are never release assets.

## Upgrade boundary

v2 intentionally does not preserve runtime aliases for removed public v1 configuration fields or the legacy rollback slot. Existing users should move declarations to the v2 schemas before upgrading. The offline `scripts/migrate_policy_v2.py` helper may be used to convert old policy documents, but migrated output must pass the same current v2 validation gates as a fresh project.
