# P13 + P15 — Transport Qualification and Source Health Guard

P13 and P15 extend the production safety boundary without changing the canonical ACL4SSR classification graph, the six public FlClash selectors, DNS ownership, or subscription reachability policy.

## P13: transport qualification

The general inventory remains available for explicit/manual user choice. Automatic routing is hardened in two tiers immediately before publication:

1. `自动选择` is restricted to nodes that pass a live HTTPS probe through the real Mihomo core.
2. `媒体自动` and `通讯自动` are restricted further to nodes with a live SOCKS5 UDP-associate path through Mihomo.

The UDP probe first sends a 1200-byte unsupported-version QUIC long-header datagram to `1.1.1.1:443`. A response proves that the selected proxy can carry UDP/443 and reach a QUIC-speaking endpoint. If that does not respond within the short timeout, a DNS UDP round-trip to `1.1.1.1:53` is used as a generic UDP fallback.

A node is therefore reported as:

- **TCP qualified** when the live HTTPS probe succeeds.
- **UDP qualified** when either the QUIC-path probe or DNS UDP fallback succeeds.
- **QUIC path observed** only when the UDP/443 version-negotiation probe receives a response.

`QUIC path observed` is intentionally not described as a full HTTP/3 application handshake. P13 validates transport reachability, not streaming throughput or application entitlement.

If no general node passes TCP qualification, or no TCP-qualified node has a working UDP path, publication fails closed and the currently published configuration remains untouched.

## P15: source health guard

Immediately before replacing the Cloudflare KV production key, clash-relay compares the fully qualified candidate with the currently published private configuration.

The comparison never publishes node names, endpoints, credentials, subscription URLs, or traffic records. Runtime proxy objects are fingerprinted privately after removing their generated names, and only aggregate counts are returned.

The guard rejects a candidate when any of these conditions is met:

- total active inventory drops by more than 50%, unless the missing source was explicitly removed from the current subscription declarations;
- an active source with at least 8 previously published nodes loses more than 60% of its inventory;
- for a browsing-enabled source, a protected region (`US`, `SG`, `JP`, `TW`, `KR`, `HK`) that previously had at least 3 nodes falls to zero.

Removing a source from `subscriptions.yaml` is treated as an intentional declaration change rather than an outage, so the removed source does not trip the per-source or total-drop guard.

P15 runs before the previous-good snapshot and before the production KV write. A rejected candidate therefore cannot replace production and cannot overwrite the recovery baseline.

## Unchanged contracts

P13 + P15 do not change:

- `runtime.dns.mode: client` or the P11 no-Fake-IP production default;
- HTTP/TLS/QUIC Sniffer settings introduced by P12;
- ACL4SSR Online rule order or the declared P10 deviations;
- the six public groups;
- browsing regional preference order;
- OpenAI / Claude / Gemini qualification;
- `subscription_1` browsing/AI-only isolation, the `>2x` filter, or the EMBY exclusion;
- dual Mihomo v1.19.30 / v1.19.29 validation;
- Cloudflare-KV-only production publication.
